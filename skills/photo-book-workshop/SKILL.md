# Photo Book Workshop

Use the installed `photo-book` command or the repository environment. Start with `photo-book --help` and the user's existing book plan if present. Keep their working folder separate from the public source. The offline demo is an independently invented reference, not a source of facts about the user's book.

Read `docs/OWN-PHOTOS.md` for selection and normalization, `docs/REFERENCE.md` for commands/units/schema, and `docs/OPTIONAL-AI.md` only when captions will use a model. In a downloaded repository these are at the repository root; if only this skill was copied, use the corresponding guides in the installed release or at https://github.com/jessecmaddox3/photo-book-workshop/tree/main/docs.

## Shape the book with the user

Establish the reader, purpose, rough length, desired tone and intended physical size when those decisions are missing. Follow an existing outline instead of replacing it with a standard formula. Use a few distinct caption alternatives where comparison helps. Keep recognizable details and supplied facts; do not invent relationships, names, locations or memories from an image. People tags are context, not evidence locating a face.

Select photos for story and composition, not just a quality score. Contact sheets preserve uncropped thumbnails. Bind numbered picks to the pool hash, then persist stable asset IDs. Reuse an image deliberately with a new placement ID. Preserve original media, normalize derivatives, and keep the private catalog's source paths, coordinates and tags out of a shareable book plan unless needed and intended.

## Build and inspect

Use mosaics for an exploratory arrangement and authored rows for a deliberate composition. Units matter: physical trim/bleed/safe/gutter are inches; layout rectangles, row heights and type sizes are points. Focus is a top-left fraction pair. Keep every selected image or record an explicit exclusion; a failed crop constraint calls for a new grouping or a deliberate setting change.

Build to a new output folder. Inspect every rendered page at reading size, including covers and front matter. Check names against user-supplied facts, full caption wording, text overflow, missing glyphs, focus/crops, image inclusion and physical dimensions. Read both source PPI and embedded proof PPI. Do not claim print readiness from source resolution alone. Obtain the chosen printer's actual specifications before a print handoff; ordering is a separate user action.

Use the local review app for explicit caption choices and notes. Preview is not selection. Notes do not become printed prose. Preserve pending drafts and conflicts; never delete state or bindings to clear an error. Apply wording edits to the plan deliberately, and use a new review workspace when its identity changes.

## Optional AI and publication

Local rendering, catalog work and the demo do not require AI. Uploading images requires applicable user authorization plus the tool's explicit enablement/consent. Review the exact previews and selected context. For Batch, require the small reviewed trial and recorded pricing, keep unknown costs reserved, and reconcile uncertain requests instead of resubmitting. A local estimate is not a provider billing limit.

Sharing a proof shares its pictures and wording. Treat catalogs, generated books, review notes, model logs and exports as private working material. Use invented fixtures for public contributions and keep the original source images and established workflow intact.
